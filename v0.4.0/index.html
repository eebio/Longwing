The Longwing Data Standard

What is the Longwing Data Standard?

The Longwing Data Standard is a data format and supporting tools to enable accessible and reproducible data processing for engineering biology.

It allows standardised and reproducible processing of plate reader and flow cytometry data.

How does it work?

The Longwing data format is composed of a structured JSON file (named the .lw file) containing the raw data (in a standardised format) and the post-processing commands that are run on the data. This means that uploading a .lw file a supplementary data for an article allows anyone to view the raw data and see (and reproduce) exactly how it was processed to derive the results seen in the article.

Since we have all the data in a standardised format, we can (and do) provide a set of methods for processing the data. This includes calibration methods, flow cytometry gating, and calculating summary statistics such as growth rate or per cell fluorescence. While we provide many possible methods for each of these, we also offer sensible, robust, benchmark-verified defaults that should work in the majority of cases.

Longwing can be used through its command line interface. If you want to learn how to use Longwing, check out the documentation.

Contributing

There are a couple of ways you can contribute towards the Longwing Data Standard.

  • If you have a method that you would like to see included in the Longwing Data Standard, please open a new issue,
  • If you have a plate reader machine that isn't currently supported (see the docs for current compatability), please open a new issue,
  • If you find a bug or mistake in the documentation, please open a new issue.

[!CAUTION] The Longwing Data Standard stores both raw data and code. Views are generated by executing code that is described in the Longwing file (under the sections transformations and views). This means calling lw views involves executing arbitrary code. Only generate views from files you have verified are safe or come from a trusted source.
